颜色格式与色值转换基础

常见颜色格式包括 HEX、RGB、RGBA、HSL 和 HSLA。HEX 以十六进制表示颜色，适合网页 CSS 和设计稿标注；RGB 用红绿蓝三个通道描述颜色，便于理解屏幕发光原理；HSL 则用色相、饱和度和亮度描述，更接近人眼对颜色的直观感受，适合做明暗和鲜艳度调整。

在实际工作中，同一个颜色可能需要在不同工具之间转换。例如设计软件中取到的 HEX 色值，可能需要转成 RGB 用于代码，或转成 HSL 方便生成同色系深浅变化。理解这些格式的对应关系，可以减少复制粘贴时的误差。

如果色值带有透明度，RGBA 和 HSLA 会更实用。透明色常用于遮罩、悬浮层、阴影和状态提示，但要注意在不同背景上的实际显示效果，最好在真实页面中验证对比度和可读性。

  • HEX：适合 CSS、设计标注和快速复制
  • RGB：适合理解屏幕色彩组成和进行通道微调
  • HSL：适合调整明暗、饱和度和生成同色系
  • RGBA 与 HSLA：适合需要透明度的叠加场景

配色方案与对比度检查

好的配色不只是颜色好看，还要保证信息层级清晰和文字可读。正文与背景之间需要足够的对比度，按钮、链接和状态提示也要在视觉上可区分。对于需要无障碍支持的页面，建议参考 WCAG 对比度标准，避免浅灰文字配白底这类常见问题。

配色方案可以从单色、邻近色、互补色和三角色等关系入手。单色方案统一但容易单调，邻近色柔和协调，互补色对比强烈适合强调重点，三角色则更活泼。实际项目中，常以中性色打底，再用一个强调色引导操作。

检查配色时，可以把界面缩小或转为灰度查看层级是否仍然清楚。如果灰度下主次不分，说明对比度和明度关系还需要调整。

  • 正文与背景对比度建议达到可读标准
  • 主色用于关键操作，辅助色用于分类和提示
  • 中性色负责背景、边框和次要文字
  • 用灰度预览检查信息层级是否清晰

网页与 UI 设计中的色库用法

在网页和 UI 设计中，色库通常需要落地为设计变量或主题配置。建议把颜色按语义命名，例如 primary、secondary、background、surface、text、border、success、warning、error，而不是直接用 red、blue 这类视觉名称。语义命名更利于换肤和团队协作。

一个完整的界面色板通常包含主色不同深浅、中性色阶梯和功能色。主色用于按钮、选中态和品牌露出；中性色用于文字、分割线和背景；功能色用于成功、警告和错误反馈。深浅阶梯可以借助 HSL 调整亮度生成，但要注意保持色相一致。

深色模式不是简单反色。需要重新定义背景、表面、文字和边框的对应关系，并适当降低高饱和色的亮度，避免刺眼。

  • 用语义化命名管理颜色变量
  • 主色、中性色和功能色分开维护
  • 深色模式需单独校准对比度和饱和度
  • 组件状态色要覆盖默认、悬停、禁用和选中

色彩学习与常见误区

色彩学习可以从色轮、明度、饱和度和对比度四个基础概念开始。色轮帮助理解颜色关系，明度决定层次，饱和度影响情绪强度，对比度关系到可读性。掌握这些概念后，再去看具体色库会更容易判断是否适合当前项目。

常见误区包括：颜色越多越丰富、只看色值不看使用面积、忽略背景影响、直接照搬流行配色。实际上，大面积色块和小面积点缀的视觉感受差别很大，同一个色值放在不同背景上也会呈现不同效果。

另一个误区是过度追求趋势色。趋势色适合短期营销和年轻化表达，但品牌核心色需要更稳定的识别度。可以将趋势色用于活动页面或辅助元素，而不必频繁更换主色。

  • 先学明度与对比度，再学复杂配色
  • 颜色效果受面积和背景影响
  • 趋势色适合辅助，不一定适合做主色
  • 多在实际界面中验证，而不是只看色卡

深色模式可以直接把颜色反过来吗？

不建议直接反色。深色模式需要重新设定背景、表面、文字和边框的层次，并适当降低高饱和色的亮度，避免刺眼。同时要重新检查对比度，确保正文、图标和状态提示在深色背景下仍然清晰可辨。
